## Analytics Core 0.3.9

Добавлены локальные Telegram-команды:

```text
/rop_today
/rop_funnel
/rop_risks
```

Команды читают только локальную `crm_raw_entities` в SQLite. Для расчёта этой версии запросы к OpenAI и Bitrix24 не выполняются.

### /rop_today

Показывает:

- количество всех сделок;
- активные / успешные / проигранные;
- конверсию закрытых сделок в успешную продажу;
- новые сделки за последние 24 часа;
- новые лиды за последние 24 часа;
- сделки без движения от 3 дней;
- критические сделки от 5 дней;
- активный pipeline по валютам;
- сумму успешных сделок по валютам;
- средний чек успешных сделок по валютам.

### /rop_funnel

Показывает:

- объём сделок;
- active/won/lost;
- конверсию закрытых сделок;
- распределение по `CATEGORY_ID`;
- топ стадий по `STAGE_ID`.

Названия воронок и стадий пока намеренно не подменяются догадками: до бизнесовой сверки показываются реальные ID Bitrix24.

### /rop_risks

Показывает:

- число активных сделок без движения от 3 дней;
- число критических активных сделок без движения от 5 дней;
- список самых долгих зависаний;
- ID сделки;
- текущую стадию;
- количество дней без движения;
- сумму и валюту;
- `ASSIGNED_BY_ID`.

## Формулы MVP

### Статус сделки

Используется `STAGE_SEMANTIC_ID`:

- `S` — успешная;
- `F` — проигранная;
- остальные значения — активная.

### Конверсия закрытых сделок

```text
won / (won + lost) * 100%
```

Это техническая формула MVP. Перед бизнесовой приёмкой её нужно сверить с определением KPI «сделка → успешная продажа» у туризма.

### Pipeline

```text
SUM(OPPORTUNITY) только по активным сделкам
```

Суммы не смешиваются между валютами.

### Успешные продажи и средний чек

```text
won_revenue = SUM(OPPORTUNITY) по успешным сделкам
average_won_check = won_revenue / количество успешных сделок
```

Это CRM-сумма успешных сделок, а не подтверждённые бухгалтерские платежи или маржа.

### Дни без движения

Для активной сделки берётся первое доступное значение:

1. `MOVED_TIME`;
2. `DATE_MODIFY`;
3. `DATE_CREATE`.

MVP-нормативы:

```env
ROP_ATTENTION_DAYS=3
ROP_CRITICAL_DAYS=5
ROP_RISK_LIMIT=20
```

- `lead → deal` как точную бизнес-конверсию;
- SLA первого содержательного ответа;

- ФИО и отдел вместо `ASSIGNED_BY_ID`;
- факт оплаты и маржу;
- выполнение плана;
- названия и бизнес-смысл каждой стадии без сверки с туризмом;
- анализ звонков и переписок.
