# Stage 3.3B — локальная синхронизация Bitrix24

Статус: Stage 3.3B.1 принят локально; версия 0.3.7 переводит первичный sync на полный ID-cursor.

## Сетевой фундамент

- единый SOCKS5-прокси для Telegram, OpenAI и Bitrix24;
- поддержка IP-whitelist без логина и пароля;
- секреты прокси не выводятся в логи;
- локально на Windows подтверждены Telegram, OpenAI и Bitrix24 через выделенный IP;
- запись в CRM запрещена: `ALLOW_CRM_WRITE=false`.

## Stage 3.3B.1 — локальная CRM-синхронизация

Команды:

```text
/bitrix_sync
/bitrix_sync_status
```

Read-only sync сохраняет в локальную SQLite:

- сделки;
- лиды;
- контакты;
- компании;
- CRM-активности;
- историю стадий сделок;
- историю стадий лидов.

Хранение выполняется в `crm_raw_entities`:

- тип сущности;
- ID сущности;
- JSON payload;
- SHA-256 payload;
- время изменения из Bitrix24, когда оно доступно;
- время локальной синхронизации.

История и прогресс запусков хранятся в `crm_sync_runs`.

## Версия 0.3.7 — Full CRM Sync

Для больших выборок используется рекомендованный Bitrix24 cursor-подход:

1. сортировка по `ID ASC`;
2. первая страница с `start=-1`;
3. следующая страница с фильтром `>ID` последней полученной записи;
4. повтор до реального конца данных;
5. каждая страница сразу сохраняется в SQLite.

`BITRIX24_SYNC_MAX_ITEMS_PER_ENTITY=0` означает отсутствие искусственного лимита по количеству записей. Положительное значение можно использовать только как диагностический/test limit.

Сохраняется отдельный аварийный предел количества страниц для защиты от зацикливания или некорректного ответа API.

Настройки по умолчанию:

```env
BITRIX24_SYNC_MAX_PAGES=20000
BITRIX24_SYNC_MAX_ITEMS_PER_ENTITY=0
BITRIX24_SYNC_TIMEOUT_SECONDS=60
BITRIX24_SYNC_RETRY_ATTEMPTS=4
BITRIX24_SYNC_RETRY_BACKOFF_SECONDS=2
BITRIX24_SYNC_PAGE_DELAY_SECONDS=0.25
```

Retry выполняется для временных transport/server/limit ошибок. Полный webhook URL не должен попадать в INFO-лог `httpx`.

## Ограничения текущего подэтапа

- синхронизация пока полная, не инкрементальная;
- таймлайн-комментарии не загружаются массово — это будет отдельный контролируемый обход;
- `COMMUNICATIONS` и файлы CRM-активностей пока явно не выбираются;
- задачи, Открытые линии, телефония, сотрудники и Диск остаются закрыты текущими правами вебхука;
- нормализованный аналитический слой ещё не построен.
