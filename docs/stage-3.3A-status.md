# Stage 3.3A — инвентаризация Bitrix24

Статус: пройдено.
Дата приёмки: 2026-08-06.

## Цель

Определить фактический read-only контур коробочного Bitrix24 перед разработкой
полного синхронизатора и ИИ-РОПа.

## Реализовано и проверено

- команда Telegram `/bitrix_inventory`;
- проверка существования и доступности методов через `method.get`;
- fallback на устаревший `methods` для старых коробочных версий;
- группировка возможностей по CRM, задачам, коммуникациям, телефонии,
  смарт-процессам, товарам, сотрудникам и файлам;
- подсчёт стандартных и пользовательских полей сделок и лидов;
- безопасное отображение методов, закрытых правами вебхука;
- отсутствие вызовов методов создания, изменения и удаления;
- данные CRM не передаются в OpenAI;
- версия проекта `0.3.3`.

## Фактическая матрица коробочного Bitrix24

Результат локальной проверки через `method.get`:

- доступно: 16 из 25 методов;
- существует, но закрыто правами вебхука: 8;
- отсутствует на портале: 1.

### Есть на портале, но закрыто правами вебхука

## Схема CRM

- поля сделок: 194 всего, 51 стандартное, 143 пользовательских;
- поля лидов: 115 всего, 59 стандартных, 56 пользовательских.

## Вывод

Ядро данных для ИИ-РОПа доступно уже сейчас: сделки, лиды, контакты, компании,
активности, история стадий, комментарии таймлайна, товарные позиции и смарт-процессы.

Для полного контура РОПа требуется расширить read-only права вебхука на сотрудников,
структуру компании, задачи, Открытые линии, телефонию и Диск.

Отсутствующий метод расшифровок звонков должен быть заменён альтернативным источником
данных коробочного Bitrix24 или отдельным сервисом транскрибации; его отсутствие не
блокирует построение основного read-only синхронизатора.

## Следующий подэтап
