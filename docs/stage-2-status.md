# Stage 2 — Telegram MVP status

Дата подтверждения: 2026-08-06.

## Подтверждённый сквозной сценарий

Рабочая цепочка проверена локально на macOS:

```text
Telegram user
  → aiogram long polling
  → Telegram user ID allowlist
  → Agency Stack handler
  → OpenAI Agents SDK
  → Agency Stack Orchestrator
  → ответ обратно в Telegram
```

## Что проверено

- Telegram-бот успешно подключается через long polling;
- `/id` возвращает числовой Telegram user ID;
- пустой allowlist запрещает доступ всем пользователям;
- разрешённый пользователь проходит проверку доступа;
- `/start` возвращает главное меню;
- текстовый запрос передаётся оркестратору;
- оркестратор возвращает ответ в Telegram;
- длинные ответы разбиваются на части;
- запись в CRM остаётся отключённой;
- OpenAI tracing остаётся отключённым по умолчанию;
- Ruff проходит без ошибок;
- тесты Stage 2 проходят локально.

## Локальная среда

Репозиторий:

```text
~/cifra-work/Agency-stack
```

Рабочая ветка:

```text
stage-2-telegram
```

Запуск Telegram-бота:

```bash
bash scripts/run-telegram.sh
```

## Секреты

В Git не сохраняются:

- `OPENAI_API_KEY`;
- `TELEGRAM_BOT_TOKEN`;
- `AGENT_API_TOKEN`;
- реальные Telegram user ID;
- локальный `.env`.

Все значения задаются только в локальном `.env` или секрет-хранилище окружения.

## Текущие ограничения

- Bitrix24 ещё не подключён;
- реальные данные сделок и клиентов недоступны;
- бот работает локально через long polling;

- история диалога между перезапусками не сохраняется;
- rate limit хранится в памяти процесса.
